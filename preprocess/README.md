# 前処理 — XDF と課題データを学習用の表にする

`task_data/` に溜まった記録を、そのままモデルに渡せる表へ一括変換します。

```bash
pip install -r lsl/requirements.txt        # pyxdf が必要（pylsl には依存しません）
python preprocess/build_dataset.py
```

引数で窓の作り方を変えられます。

```bash
python preprocess/build_dataset.py --window 10 --hop 2 --horizon 20
python preprocess/build_dataset.py --no-gaze-samples      # 視線の生データを書かない
python preprocess/build_dataset.py --task-data task_data --out dataset
```

---

## 出力

`dataset/` に出ます（`.gitignore` 済み）。すべて `utf-8-sig`、列名は日本語です。

| ファイル | 1行の意味 |
|---|---|
| `coverage.csv` | セッション × ストリーム。**最初にこれを見てください** |
| `surface_fit.csv` | 座標変換の当てはまり採点（4通り） |
| `gaze_regions.csv` | 視線1サンプル。領域・ブロック・設問つき |
| `features_step.csv` | 被験者 × 問題 × 設問 |
| `features_window.csv` | 被験者 × 問題 × 窓 |

### `coverage.csv` を先に見る理由

セッションごとに欠け方が大きく違います。**欠けたまま黙って学習に流すのが一番危ないので、件数を必ず表に出します。**

`判定` 列でそのセッションが使えるかが分かります。

| 判定 | 意味 |
|---|---|
| `使用可` | 特徴量を作った |
| `中断` | 途中で止めた回。XDF の末尾が欠け、課題データも保存されていない |
| `課題データなし` | XDF はあるが `events.csv` が無い |
| `視線なし` | サーフェスが一度も検出されなかった |
| `整列不可（task_startなし）` | 時刻の原点が無く、他のデータと突き合わせられない |
| `XDFなし` | 課題データだけがある |

**`中断` は異常ではありません。** 記録を途中で止めた回はこうなります。特徴量は作らずに飛ばします。

`注記` 列には、切り落としたバイト数やファイルの対応づけの失敗が入ります。

---

## 時刻の合わせ方

XDF の中は LSL のローカル時計、課題ページは「開始ボタンからの経過ミリ秒」。この2つをつなぐのは `ExperimentMarkers` の **`task_start` ただ1点**です。

```
XDF時刻 = task_start の LSL時刻 + 経過秒
```

読み込んだ時点で全ストリームを経過秒へ直すので、以降の処理は LSL 時計を意識しません。記録開始は課題開始より前なので、`経過秒` は負の値から始まります。

**`task_end` には頼りません。** 実際の記録では入っていませんでした。課題の終端は `events.csv` のセッション行の `終了経過ミリ秒` を使います。

**途中で切れた XDF も読みます。** 記録を途中で止めると末尾のチャンクが欠け、`pyxdf` が `struct.error` で落ちます。最後の完全なチャンク境界まで切り落として読み直し、`注記` に残します。切り落とされるのは数十バイトなので、データの損失は実質ありません。

---

## 視線の座標系

`layout.csv` はウィンドウ座標（左上原点）、Pupil のサーフェス座標は左下原点です。向きが違うので変換します。

```
x_window = x_surface        （左右はそのまま）
y_window = 1 - y_surface    （上下は反転）
```

**この向きは実データで確かめたものです。** 視線 x の分布が二山になり、細い山（0.10〜0.25、全体の14%）が `layout.csv` のコード文字範囲（0.02〜0.22）と重なり、幅広い山（0.55〜0.95、86%）が設計書側（0.50〜1.00）と重なりました。y はコードの x 帯に絞って検証し、文字範囲に入る割合が反転あり 52.8% / 反転なし 32.3% でした。

**縦のずれと伸びは残っています。** タグはベゼルに貼るためサーフェスは画面より広く、実測の山は該当ブロックの範囲より広く散ります。そのため変換は決め打ちにせず、`Transform` の係数（`scale_y` / `offset_y`）で調整できる形にしてあります。セッションごとの当てはまりは `surface_fit.csv` の `文字範囲一致率_コード帯` で確認してください。**この値が 50% を大きく下回るセッションは、ブロック別の特徴量を信用しないでください。**

### 何を見ていたか

| 視線の位置 | 割り当て |
|---|---|
| コード領域（`x < 0.5`） | ブロックID `B1`〜`B6` |
| 設計書領域（`x >= 0.5`） | その時刻に表示していた設問 `Q1`〜`Q6` |
| サーフェス外 | `画面外` |

設問は1度に1つしか出ないので、設計書側の「大問」は設問滞在イベントから一意に決まります。

`サーフェス内` 列は Pupil の `on_surface` フラグ、`領域` 列はこちらの判定結果です。フラグが立っていても座標が範囲外の点があるため、両者はわずかにずれます。

## ラベル

**目的変数は介入要請のタイミング**です。ヒントボタンが押されると `support` マーカーが入ります。

| 列 | 内容 |
|---|---|
| `介入要請あり` | 窓の終わりから `horizon` 秒以内に `support` があれば 1 |
| `介入要請までの秒数` | 次の `support` まで。無ければ空欄 |
| `理解度正誤` | 直後の理解度テストの正誤（補助ラベル） |
| `条件` | 学習用 / 検証用 |

**正例が0件のときは、実行の最後に警告を出します。** 1回目の記録ではヒントが一度も押されず、正例は0件でした。**この状態では介入タイミングの学習はできません。** 変換と対応づけの確認までは進められます。

理解度テストは補助ラベルです。設問1つに対して1問なので、`features_step.csv` の行にそのまま付きます。Q6（自己評価）には理解度テストが無いので空欄になります。

## 特徴量

区間の切り出し方だけを変えて、設問単位と窓単位で同じ関数を使います。**値が取れないときは NaN を返し、行は落としません。** 落とすかどうかは学習側で決めてください。

### 脳波（Muse 4ch / 256 Hz）

1〜40 Hz の帯域通過（Butterworth 4次、ゼロ位相）→ Welch。帯域内を積分した値（µV²）です。

`θ` 4〜8、`α` 8〜13、`β` 13〜30、`低γ` 30〜40 Hz。加えて `脳波_θα比` と `脳波_前頭左右差α`（AF7 と AF8 の α の対数比）。

`脳波_振幅超過率` は 200 µV を超えたサンプルの割合で、1割を超えると `脳波_品質` が `振幅過大` になります。**TP9・TP10 は耳電極でノイズが大きく、前頭より1桁高い値が出ます。** チャネル間で直接比べないでください。

### 心拍（Garmin Venu 3S）

`hr_bpm` と `rr_ms` の JSON から、平均HR・RMSSD・SDNN・pNN50。RR は 300〜2000 ms の外を捨てます。`rr_ms` は数値でもリストでも受けます（実データは数値でした）。

**5秒窓では RR が数拍しか入りません。** RMSSD や pNN50 を使うなら `--window` を伸ばしてください。

### 瞳孔

**`diameter_2d`（px）を主に使います。** `diameter_3d`（mm）は1回目の記録で約半分が NaN で、値が出ているときも eye0 が 1.36、eye1 が 2.17 と左右で60%食い違いました。3D 眼球モデルが校正されていないと判断しています。`瞳孔_3d有効率` で状況を確認できます。

**px は絶対値に意味がありません。** 目とカメラの距離で変わるので、学習側でセッションごとに標準化してください。

### 注視

`fixation_id` でまとめて数えます。**`注視_平均時間ms` は1回目の記録では 307〜308 ms でほぼ一定でした。** Pupil 側の検出設定によるものと見られ、この記録では情報になりません。`注視_回数` を使ってください。

### 視線

領域とブロックの割合、コードと設計書の `往復回数`。割合の分母は画面内にあったサンプルで、画面外の割合は `視線_画面内率` で別に持ちます。

**ブロック列は `B1`〜`B6` の固定です。** 問題によってブロック数が違うため（pA は5個、pC と pD は6個）、無いブロックの列は 0 になります。コード側のサンプルが1つも無い窓では NaN です。

---

## 設問単位の作り方

設問は行き戻りがあるため、1つの設問に複数の訪問区間が対応します。訪問ごとに特徴量を出し、滞在時間で重み付けして1行にまとめます。件数と回数の列だけは合計します。

`滞在ミリ秒` と `訪問回数` は、課題ページの JSON の `設問別合計` と一致することを確認済みです。

---

## ファイルの対応づけ

XDF は `/start` の時刻、JSON 以下は `/save` の時刻で名前が付くため、**時刻印は一致しません。** JSON の中の `XDFファイル` の**ファイル名部分**で照合します（中身は記録した機械の絶対パスなので、パスは使いません）。

見つからない場合は、同じフォルダに XDF が1つだけならそれを使い、`注記` に残します。

## モジュール

| ファイル | 役割 |
|---|---|
| `build_dataset.py` | CLI と一括処理の入口 |
| `xdf_io.py` | XDF 読み込み、`task_start` 基準への整列、破損した末尾の切り落とし |
| `task_io.py` | `events.csv` / `layout.csv` / `answers.csv` / JSON の読み込みと対応づけ |
| `regions.py` | 座標変換、領域とブロックの判定、当てはまり採点 |
| `features.py` | 脳波・心拍・瞳孔・視線の特徴量 |

`lsl/view_xdf.py` の `stream_name()` / `channel_labels()` を使い回しています。同じ読み方を二重に持たないためです。
