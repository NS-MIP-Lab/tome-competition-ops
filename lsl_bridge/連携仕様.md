# 生体計測との連携仕様

課題ページ（詳細設計書作成課題）が LSL に流すマーカーの仕様と、収録・解析の手順をまとめたものです。脳波・心拍・視線の収録を担当される方向けです。

操作手順は [README.md](README.md) を、課題そのものの実施手順は [../実施手順.md](../実施手順.md) を参照してください。

---

## 1. 全体構成

```
Muse       -> LSL -----------------------+
Pupil      -> LSL -----------------------+--> LabRecorder --> experiment.xdf
Venu 3S    -> BLE -> garmin_hr_lsl.py ---+
課題ページ -> WebSocket -> bridge.py ----+
```

課題ページはブラウザ上で動きます。ブラウザから liblsl を直接呼ぶことはできないため、`bridge.py` を仲介させています。ページは操作イベントを WebSocket（`ws://127.0.0.1:8001`）で送り、`bridge.py` が `pylsl` でマーカーを流します。

実施環境は Mac 1台を想定しています（課題・Garmin ブリッジ・LabRecorder が同一機）。別マシンに分ける場合も LSL は同一 LAN 上で動作し、時計のずれは LSL 側で補正されます。

## 2. ストリーム仕様

| 項目 | 値 |
|---|---|
| name | `DesignTask_Markers` |
| type | `Markers` |
| channel_count | 1 |
| nominal_srate | 0.0（不規則） |
| channel_format | `string` |
| source_id | `design_task_markers` |

`bridge.py` の起動と同時に作られます。**被験者が座る前から LabRecorder のストリーム一覧に現れる**ので、収録対象に含め忘れることがありません。

サンプルのタイムスタンプは、`bridge.py` がイベントを受信した時点の `pylsl.local_clock()` です。

## 3. マーカーの中身

1チャンネルの文字列に、UTF-8 の JSON を1件入れます。

```json
{"seq":1,"event":"start","t":"2026-08-10T10:00:00+09:00","problem":"p5","mode":"learning","subject":"S01"}
```

### 全イベント共通のフィールド

| キー | 型 | 内容 |
|---|---|---|
| `seq` | 整数 | 1 から始まる連番。**欠番があれば取りこぼし** |
| `event` | 文字列 | イベント種別（下表） |
| `t` | 文字列 | ページ側の壁時計時刻（ISO 8601、タイムゾーン付き） |
| `problem` | 文字列 | 問題ID。`p5`＝エラトステネスのふるい、`p3`＝挿入ソート、`p6`＝カデイン法 |
| `mode` | 文字列 | `learning`＝学習用（ヒントあり）／`test`＝検証用 |
| `subject` | 文字列 | 被験者ID |

問題IDを記号にしているのは、URL や画面にアルゴリズム名が出ると被験者に手がかりを与えてしまうためです。

### イベント別の追加フィールド

| `event` | 発生タイミング | 追加フィールド |
|---|---|---|
| `start` | 「開始する」を押した瞬間。**ここが t = 0**。ソースコードの表示と同時 | なし |
| `step_enter` | 設問が画面に表示された | `step`（`Q1`〜`Q9`）、`index`（何問目か。1 起点） |
| `step_leave` | その設問を終えて次へ進んだ | `step` |
| `quiz_open` | 理解度テスト（4択）が全画面で表示された | `step`（直前の設問）、`items`（出題数） |
| `quiz_submit` | 理解度テストに回答した | `step`、`correct`（正答数）、`total`（出題数） |
| `finish` | 「回答を終える」を押した | なし |
| `hint` | ヒント要請ボタンが押された（**学習用のみ**） | `step`、`seq_hint`（その被験者の中で何回目か） |

設問の順序は `Q1 → Q2 → Q3 → Q4 → Q5 → Q9` です。Q6〜Q8 は存在しません（設計書の構成上の欠番）。

理解度テストは各設問の直後に出ます。ただし Q9 の後には出ません。

### 時系列の例（学習用）

```
start
step_enter(Q1) … hint(Q1) … step_leave(Q1)  quiz_open(Q1) quiz_submit(Q1)
step_enter(Q2) …              step_leave(Q2)  quiz_open(Q2) quiz_submit(Q2)
…
step_enter(Q9) …              step_leave(Q9)  finish
```

**`step_enter` から `step_leave` までが、その設問を記述していた区間です。** 理解度テストはこの区間の外に出してあるので、設問の区間にテストの時間は混ざりません。

`quiz_open` から `quiz_submit` までは4択に答えている時間で、設計書の記述はしていません。設問単位の解析では除外するか、別条件として扱ってください。

Q9 の後にはテストが無いため、`step_leave(Q9)` の次は `finish` です。

## 4. 時刻の扱い

### t = 0 の定義

`start` マーカーの LSL 時刻です。この瞬間に被験者の画面へソースコードが表示されます。それ以前は「開始する」ボタンのある説明画面で、コードは伏せられています。

### 精度

ブラウザでのイベント発生 → localhost の WebSocket → `pylsl.push_sample` までで、**数ミリ秒程度**の遅延があります。設問単位・ヒント単位の事象関連分析には十分ですが、ミリ秒未満の精度が必要ならハードウェアトリガの導入を検討してください。

遅延の内訳はブラウザのイベントループと OS のスケジューリングが支配的で、通信自体はほぼ無視できます。

### 2種類の時刻

マーカーには LSL 時刻とページ側の壁時計時刻（`t`）の両方が残ります。前者が解析用、後者は記録の突き合わせや、書き出したファイルとの照合に使います。

## 5. 課題側の書き出しファイルとの突き合わせ

課題ページは終了時に JSON と CSV を書き出します（既定のダウンロードフォルダ）。ファイル名は `design_p5_learning_S01_20260810_1000.json` の形式です。

JSON には次が含まれます。

```json
{
  "モード": "学習用",
  "アルゴリズム": "エラトステネスのふるい",
  "被験者ID": "S01",
  "開始時刻": "2026-08-10T10:00:00+09:00",
  "回答終了時刻": "2026-08-10T10:24:31+09:00",
  "LSL同期": "あり",
  "LSL開始時刻": 123456.789,
  "LSL終了時刻": 124927.512,
  "LSLマーカー": [
    {"通番": 1, "イベント": "start", "時刻": "2026-08-10T10:00:00+09:00", "lsl時刻": 123456.789}
  ],
  "ヒント要請": [
    {"通番": 1, "時刻": "...", "設問": "Q3", "LSLマーカー通番": 12, "LSL時刻": 123901.4}
  ],
  "理解度テスト": [ ... ],
  "回答": [ ... ]
}
```

**`通番` が XDF 側の `seq` と一対一で対応します。** これで「どの回答がどの脳波区間に対応するか」を推測なしに結び付けられます。

### pyxdf での読み出し例

```python
import json
import pyxdf

streams, header = pyxdf.load_xdf("experiment.xdf")
markers = next(s for s in streams
               if s["info"]["name"][0] == "DesignTask_Markers")

events = [
    {**json.loads(sample[0]), "lsl_time": float(ts)}
    for sample, ts in zip(markers["time_series"], markers["time_stamps"])
]

t0 = next(e["lsl_time"] for e in events if e["event"] == "start")

for e in events:
    print(f"{e['lsl_time'] - t0:8.3f}s  {e['event']:<12} {e.get('step', '')}")
```

### 取りこぼしの確認

解析の前に必ず実行してください。

```python
seqs = [e["seq"] for e in events]
missing = sorted(set(range(1, max(seqs) + 1)) - set(seqs))
print("欠番:", missing or "なし")
```

欠番があれば、そのマーカーは XDF に入っていません。`bridge.py` が同時に書いている `lsl_bridge/logs/markers_*.csv` に該当行があるか確認してください。CSV にあって XDF に無ければ収録側の問題、どちらにも無ければ送信側の問題です。

### 設問ごとの区間を切り出す

```python
def spans(events, step):
    enter = next(e for e in events
                 if e["event"] == "step_enter" and e.get("step") == step)
    leave = next(e for e in events
                 if e["event"] == "step_leave" and e.get("step") == step)
    return enter["lsl_time"], leave["lsl_time"]

print(spans(events, "Q3"))
```

## 6. 実験当日の起動順

1. Muse・Pupil・Garmin の各ストリームを立ち上げる
2. `cd lsl_bridge && source .venv/bin/activate && python bridge.py --open`
3. LabRecorder を開き、`DesignTask_Markers` を含む全ストリームを選択して録画開始
4. 課題ページ（`http://127.0.0.1:8000/index.html`）で問題と条件を選び、被験者に実施してもらう
5. 課題終了後、LabRecorder を停止する
6. 書き出された JSON / CSV と XDF、`lsl_bridge/logs/` の CSV をまとめて回収する

**課題ページは必ず `http://127.0.0.1:8000` から開いてください。** ファイルをダブルクリックして開くと LSL 連携は無効になり、マーカーが一切記録されません。ページの「はじめに」画面で接続状態が緑になっていることを確認してから開始してください。未接続では開始できないようにしてあります。

## 7. 決めていただきたいこと

### 録画の開始方法

現状は **LabRecorder を手動で先に開始し、`start` マーカーで t = 0 を定義する**方式です。

`bridge.py` の `LABRECORDER_ENABLED` を `True` にすると、`start` で録画開始・`finish` で停止を LabRecorder へ送れます（TCP 22345）。ただし**既定では無効**にしてあります。理由は次のとおりです。

- Muse は装着直後は不安定で、落ち着くまで時間が要る
- Pupil は較正が必要
- 開始前のベースライン区間が取れなくなる
- LabRecorder 側でリモート制御を有効にする必要があり、コマンド書式がバージョンで異なる

自動化する場合は、上記を踏まえて判断してください。有効にしても課題ページ側の変更は不要です。

### ファイル名と保存先

自動制御を有効にする場合、`bridge.py` の `handle_recording()` で LabRecorder に渡すテンプレートを決める必要があります。現状は `sub-<被験者ID>_task-<問題ID>-<条件>_run-<連番>.xdf` としてありますが、既存の命名規則に合わせて変更してください。

### 収録するストリームの構成

Muse と Pupil のストリーム名がこちらでは未確認です。LabRecorder で全選択すれば漏れませんが、名前を教えていただければ確認手順に追記します。

## 8. 制約と注意点

- **課題ページを再読み込みすると、そのページが保持していたマーカー一覧は失われます。** ただし XDF と `lsl_bridge/logs/` の CSV には残っているので、解析には影響しません
- **`Garmin_HR` の LSL 時刻は BLE 通知の受信時刻**であり、心拍の発生時刻ではありません（`garmin_mac_lsl/README.md` の注意書きを参照）。脳波との厳密な同期評価では、このマーカーストリームを基準にしてください
- 接続が切れた状態で操作された場合、そのイベントは課題側の書き出しに `未送信` として残ります。黙って捨てることはありません
- `bridge.py` は `127.0.0.1` のみで待ち受けます。外部から接続されることはありません

## 9. 動作確認

### ストリームが見えるか

```bash
python - <<'PY'
from pylsl import StreamInlet, resolve_byprop
s = resolve_byprop("name", "DesignTask_Markers", timeout=3.0)
print("見つかりました" if s else "見つかりません")
if s:
    inlet = StreamInlet(s[0])
    while True:
        sample, t = inlet.pull_sample()
        print(f"{t:.6f} {sample[0]}")
PY
```

`garmin_mac_lsl/check_lsl.py` と同じ要領です。この状態で課題ページを操作すると、マーカーが流れてくるのが見えます。

### LSL 無しで動作だけ確認する

```bash
python bridge.py --no-lsl
```

`pylsl` を使わず、受信内容の表示と CSV 記録だけ行います。課題ページ側の動作確認に使えます。

## 10. うまくいかないとき

| 症状 | 確認すること |
|---|---|
| ページに「接続できていません」と出る | `bridge.py` が起動しているか。ポート 8001 が他プロセスに使われていないか |
| LabRecorder にストリームが出ない | `bridge.py` を `--no-lsl` なしで起動しているか。liblsl が入っているか（`brew install labstreaminglayer/tap/lsl`） |
| マーカーは流れるが XDF に無い | LabRecorder で `DesignTask_Markers` を選択したか |
| `seq` に欠番がある | `lsl_bridge/logs/markers_*.csv` と突き合わせる。CSV にあれば収録側、無ければ送信側の問題 |
| ページを開いても LSL モードにならない | `http://127.0.0.1:8000` から開いているか（`file://` では無効）。URL に `?lsl=0` が付いていないか |
| `pylsl` が見つからないと出る | venv を有効化したか（`source .venv/bin/activate`） |
